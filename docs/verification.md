# 当前验证与边界

核心、CLI、记录、定时任务和 HTTP 服务使用 Rust；浏览器逻辑和原生插件桥接使用严格 TypeScript。只维护当前独立资源模型：七种完整资源类型、共享上游来源和内部支持依赖、完整 Skill 树和每项资源自己的配置正文。原型与迁移过程以 Git 历史和历史文档为准。

以下为开发侧转换验证；本机部署与上游刷新验收分别记录在交付 MR，当前运行状态以“纳管覆盖”“运行状态”页面为准。

## 自动检查

当前验收按[第一阶段验收表](acceptance.md)维护；测试数量与结果以对应提交 CI 为准，1 项需要真实模型凭据的测试默认忽略。all-target Clippy、格式、release 构建与严格 TypeScript 检查通过；浏览器与 CI 的最终结果见交付 MR。回归覆盖独立资源类型、共享来源获取、完整 Skill 树及镜像、资源配置正文、审核指纹接管、路径与符号链接边界、共享目标失败保护、原生配置保留、来源验证、禁用状态、嵌套规则、遗漏与漂移检查、提案审核、本机私有值绑定和记录保留。

启动回归验证：联网刷新前完成本地自维护内容应用和采集索引；完整计划就绪前保留旧资源。缺失上游成员只影响对应资源，MCP 私有值缺失不会阻塞无关规则。原生安装的清单身份必须在更新前匹配；失败状态从重新读取的真实原生登记生成。

浏览器回归使用拒绝写操作的只读预览，检查完整 Hook 配置与脚本编辑、改名、依赖保留及最后使用者移除。 来源／类型视图还验证同源混合类型分组、自维护来源独立、原生折叠、筛选保留及结果自动展开；桌面和 390px 布局无页面横向溢出，Enter／Space 展开收起已通过浏览器输入验证。所有提交请求均被拦截，未创建真实提案、MR 或原生更新；这证明页面行为和请求内容，实际外部提交仍由正常交付流程验证。


导入资源保留原始字节与执行位，包括 Markdown 硬换行所需空格，不通过代码格式化改写其内容。

纳管覆盖每次请求继续实时扫描。所有权按路径建立单次扫描索引；同一个物理文件的内容指纹与执行权限在该次扫描中只读取一次，下一次扫描重新读取。实际目录的旧版／新版扫描结果逐项相同（检查时间除外）；本机候选版本的页面请求约 0.9 秒，旧版约 4.8 秒，具体交付测量及部署结果记录于对应 MR。

## 真实来源与目录预检

实际通过原生安装器生成 ECC 2.2.3 内容，取得 1,066 个唯一目标，其中 488 个额外文件的内容哈希与执行位均匹配发布包。新生成器重新输出同一批目标，逐项字节与执行位完全一致；验证没有执行资源描述的业务流程。

831 个完整资源引用 19 个共享来源，覆盖 10 个项目并声明 10 项原生安装策略。230 个 Skill 资源使用 366 个完整目录树投影，另有 103 个原生 Skill 目录适配器。33 个自维护树投影资源共用 33 个正文目录，覆盖 45 个客户端目标；两个主目录独有的来源说明通过文件覆盖保留。临时副本验证确认，向共享正文增加辅助文件会同时投影到两个镜像，并保留主目录独有的元数据。

`/tmp/sm-complete-resource-units-report.json` 对比调整前后的完整声明：4,046 个唯一普通文件目标的字节和执行位相同，8 个原生配置目标的值与数组顺序相同。48 个资源通过 49 个可编辑 JSON 正文片段保有原生配置。 预检另发现现有用户 Skill `easygo-app-checks`，按原 `.codex/skills` 路径登记三个文件的完整树，新增文件指纹无旧所有者；其字节与完整文件权限逐项核对一致，不计入前述 4,046 个旧目标的等价转换，也未执行业务脚本。两个 Hindsight 实现程序及其相关事件分别归入每个客户端的完整 Hook；其他无关 Hook 保持独立。
