# Rust 迁移验证记录

本次核心、CLI、记录、定时任务与 HTTP 服务全部迁移为 Rust；浏览器逻辑和回归驱动改为严格 TypeScript。原 Python 包、pyproject.toml、Python 测试与启动入口已移除。页面、脚本、提示和服务模板嵌入原生二进制；没有转发到旧 Python 实现的兼容包装层。

测试全部使用临时 Git 远端、临时用户目录与外部接口替身。没有初始化真实用户服务、运行生产 MCP 或机器人任务。初版的历史证据见[历史验证记录](history/2026-10-21-initial-verification.md)。

当前结果：78 项 Rust 常规回归通过；独立执行的真实分析器验证通过（Codex、Kimi 各一次空候选请求）；TypeScript 严格检查、三项浏览器回归、格式、Clippy 和 release 构建通过。

## 兼容与行为

- 以已审核初版实际生成的 SQLite SQL、JSONL、采集配置和提案元数据为夹具；Rust 能读取原所有权、观察、偏移和提案编号，异常数据报错而不清空。
- 已安装资源和旧 Python 采集入口能继续同步；切换后每个事件只保留一份 SM 处理器，无关 Hook、配置、注释和权限保留。
- 旧读取器也实测可读取 Rust 写出的所有权、资源、提案和观察，回退不要求清理数据库。
- 旧记录不重复消化，新记录继续追加；原资源哈希、事件标识和 Unicode 提案编号兼容。已有待审 Git 分支继续在原目录／MR 更新。
- 两个临时 home 使用同一项目约定恢复相同内容；项目 Skill 不进入用户目录。待审内容不生效，合并后再同步更新。
- 经过审核的改名、作用域调整和移除清理旧受管位置，保留无关文件；冲突时不删除旧投放。二进制附件和执行位受回归覆盖。
- 上游新提交直接应用，不调用分析器、不创建优化 MR。一次使用的冗余步骤能形成带证据和前后文本约束检查的 Draft 提案，原生效内容保持不变。
- Native CLI 覆盖 init、sync、status、空 cycle、安静且不阻塞的 record、失败后保留提案的 propose，以及实际 serve 首次同步与嵌入页面。init 的 systemctl 使用临时替身。

## 类型、边界与检查

资源内容、来源、作用域、客户端、写入内容、应用状态、候选操作、验证结果、命令分派和 HTTP 输入使用枚举／结构体。任意 JSON 仅保留在原生配置、Hook 事实、CLI 协议包及历史运行结果等开放边界；无 any 或忽略类型错误的前端实现。

```sh
cargo test --locked
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
npm run check
npm run build
SM_BROWSER_URL=<隔离服务地址> npm run test:browser
git diff --check
```

Rust 不使用自编写 unsafe。Python 资源的语法检查使用 Tree-sitter，不调用解释器；Shell 只做 bash -n，不执行工作流。子进程使用独立进程组与非阻塞管道，同一超时覆盖进程退出及全部输入输出，错误会脱敏并保留。GitLab 合法的 nullable 描述有专门边界回归。

## 真实浏览器

browser-harness 连接真实 Chrome，服务由 Rust Axum 程序提供，页面加载编译后的 ES 模块。完成四个视角、五类资源、原生不支持状态、通用 Skill 隐藏客户端选项、创建、改名与归属调整、申请移除、证据和运行状态、390px 窄屏检查。

## 真实 CLI 与未验证边界

原生分析器验证单独执行并记录，Codex、Kimi 均返回了可反序列化的空候选对象，只输入静态空任务，业务工具关闭；它不属于普通 cargo test，也不证明诊断质量。真实用户 systemd 注册和次日调度、生产任务以及物理第二台机器恢复未执行。GitLab MR 业务行为以接口替身覆盖，迁移代码本身的交付 MR 另行记录。

优化验证仍是静态与已批准文本约束，不宣称业务效率已提高；候选保持部分验证、Draft MR 和人工审核。原生 Hook 的全事件送达仍未逐项实测，未观测不等于未使用。普通运行不需要 Node；可选浏览器验收依赖外部 browser-harness 工具，该工具的连接桥不属于 SM 运行时。


## 实现裁定

- 采用 Rust 核心和严格 TypeScript，复用已确认的产品行为；代价是构建需要 Rust 工具链和 C 编译器，运行不再需要 Python。
- CLI 使用类型化 Serve 分派，HTTP 与完整启动器在 Web 任务一起接通；实际可执行文件和浏览器已验收，未留下临时 Web 实现或双运行时选择。
- 三名独立审查者分别检查整体行为、Rust 边界与 TypeScript；各自不评判的语言／基础设施范围由其他审查和主实现者的检查补齐。前端沿用 strict 编译、产物一致性与真实浏览器检查，未新增 ESLint；代价是有限回归与这些工具不能覆盖所有输入或额外风格规则。
- 真实用户服务、生产 GitLab 工作流、物理第二台机器、Hook 全事件投递及 Kimi 任意用户 Hook 的隔离没有实测，保留为部署验收边界；代价是不能据此宣称真实环境已经生效或完全隔离。
- 空候选传输只证明 CLI 协议可用，不评判模型诊断质量；优化仍通过部分验证的 Draft MR 和人工审核。代价是建议质量与业务收益仍需真实记录和审核确认。

## 最终审查修复

最终审查的两项重要问题在同一修复阶段完成，均先观察失败再修复，全量 78/78 通过，没有遗留的轻微问题：

- `subprocess_deadline_includes_pipes_inherited_after_parent_exit`：父进程退出后，后台进程仍持有管道，原实现等待约两秒且超出 100ms 截止时间。改为非阻塞输入输出与统一截止时间，覆盖无输入和大输入；另有 1MiB 同时输入输出检查，超时会终止原进程组。
- `runtime_failure_blocks_shared_configuration_and_old_asset_cleanup`：A 的新路径被本地普通文件阻塞，原实现跳过共享配置却删掉 B 的旧脚本，留下失效引用。现在写入失败立即传递阻断共享目标及相关清理，相关资源不再报告成功；覆盖 A／B 两种先后顺序，移除阻碍后能继续应用。该问题也存在于旧版，仍按用户影响修复。
