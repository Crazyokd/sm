# 用户与项目资源纳管

工作台的“纳管覆盖”页面实时检查用户资源目录及已登记项目，区分 SM 管理、原生安装器管理、未纳管、本地变更与检查错误。`sm inventory` 提供相同的机器可读结果。新增资源不会因为未写入清单而从检查结果里消失。

当前清单包含 1,041 个独立资源、19 个共享上游来源、10 个项目和 10 项原生安装策略。资源按 Skill、Hook、规则、Agent、MCP、提示词、策略、脚本这八种实际类型逐项管理；来源与用户／项目作用域是独立维度。同一上游只共享获取过程，各项资源分别展示状态、内容、记录与改进提案。

在 SQLite 状态副本和真实目录上执行的只读预检识别 1,846 项资源：未纳管 0、漂移 0、检查错误 0、本地应用失败 0、残留旧归属 0；副本接管后包含 4,114 项所有权记录。这是开发侧转换预检证据；本机部署与上游刷新验收分别记录在交付 MR，当前运行状态以本机页面为准。

完整 Skill 使用目录树投影，新增、删除的辅助文件随同一 Skill 来源变化。229 个资源声明使用 365 个 Skill 树投影，另有 103 个既有原生 Skill 目录适配器。自维护 Skill 的客户端镜像共用一个可编辑正文目录；主目录独有的来源说明通过独立文件覆盖保留，不扩大旧镜像的目标集合。普通脚本和库模块逐项登记为脚本资源。

Hook 按原生配置组、MCP 按服务、规则与提示词按实际文件独立登记。59 个自维护配置片段分别保存在所属资源目录的 JSON 文件中，通过 `Fragment` 投影合并进原生 JSON/TOML 配置；AI 改进提案可以单独编辑该资源正文。未知配置字段、数组顺序、本机凭据和禁用状态受到保留。Codex 按名称或路径禁用的 Skill 单独注明配置来源，不推断 Kimi 也已禁用。

来源标签使用“自行维护／上游拉取”。自行维护包括自建内容及明确接管的本地改编，不代表认定全部内容由用户原创；来源未核实的资源保留说明。已存在的 Claude/Cursor 文件及原生运行依赖按其实际路径登记，不新增这些客户端的运行时适配器。项目内嵌套的 AGENTS.md/CLAUDE.md 也纳入检查；生成物、依赖、缓存和其他已登记项目有明确边界。

已有文件必须匹配经过 MR 审核的接管指纹和执行权限，才能记录所有权。身份拆分仅从明确指定且仍匹配当前状态的旧所有者转移；配置片段只扣除被接管的准确子集。接管在状态事务中完成，不改写安装文件。内容不匹配继续报冲突。已审核的上游文件在刷新离线时可按声明的文件或 Skill 树边界接管，刷新失败仍单独报告。

启动先完成本地接管、自维护内容应用和采集索引，再刷新上游；尚未刷新的内容标记为同步中。共享来源获取成功后，缺失成员只使对应资源失败并保留原安装，其余成员继续处理。抓取或原生安装器执行失败、非法路径、符号链接和格式错误仍明确失败。共享目标的失败保护继续生效，MCP 私有值缺失不会阻塞无关规则。

ECC 从上游正式发布的 npm 包获取，通过原生 Skill 安装器生成选定内容；命令模板与 Agent 定义由 Rust 转换为原生格式。生成器直接输出目标相对路径和旧客户端镜像。其他已确认来源的 Skill 也交给原生安装器，在临时目录物化后只投影已声明成员。上游正文不进入自维护改进流程。ECC 已移除的 motion-ui 保留现有内容并转为自维护，来源说明随资源保留。

Codex/Kimi 插件使用各自原生生命周期更新，不复制插件缓存。安装策略与启停意图由 SM 管理；页面的“申请启用/禁用”创建 MR，经审核合并、下一次同步后生效。运行时凭据、原生信任状态和会话数据不进入资源仓库；需要本机值的配置可使用同位置 `${SM_LOCAL}` 绑定。

只读原生登记确认 Kimi 当前四项插件均启用。新增的 `kimi-open-code-review` 策略登记此前更新器已创建的同名原生安装；旧 `kimi-open-code-review-codex` 安装和启用状态继续保留。旧选择器与上游清单身份不一致的刷新明确失败，在安装前终止，保留既有安装；不会悄然创建未声明身份。插件失败后的已有状态须重新读取验证，不能把计算中的更新意图当作成功记录。

旧仓库迁移中三个失效 Claude Skill 链接属于已完成的历史清理，不再列为待应用工作。相关精确匹配保护继续保留：用户改过的链接、普通文件或恢复有效的链接均受到保护。项目 Skill 不通过用户级别名重新扩大作用域。

检查范围是当前用户及清单约定的项目目录；系统级资源、客户端自身的内置资源和认证/历史数据继续由原生平台维护。原生插件／文件已登记与 Agent 实际加载成功分别展示；新插件通常需重新加载或开启新会话。资源改进保持证据、MR、人工审核合并、下次拉取应用的流程。
