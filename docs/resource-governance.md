# 用户与项目资源纳管

工作台的“纳管覆盖”页面实时检查用户资源目录及已登记项目，区分 SM 管理、原生安装器管理、未纳管、本地变更与检查错误。`sm inventory` 提供相同的机器可读结果。新增资源不会因为未写入清单而从检查结果里消失。

本次登记 131 个资源声明、10 个项目与 9 个原生插件安装。开发侧按真实目录和数据库副本预检发现 1,670 项实际资源：未纳管 0、本地变更 0；三个声明过的失效链接将在应用时精确清理。这是接管预检数字，当前运行状态以本机页面为准。

Skill 保持通用内容；原生规则、提示词、执行策略和配置以资源集合投放到原有路径。项目内嵌套的 AGENTS.md/CLAUDE.md 也纳入检查；生成物、依赖、缓存和其他已登记项目有明确边界。Codex 按名称或路径禁用的 Skill 单独注明配置来源，不推断 Kimi 也已禁用。

来源标签使用“自行维护／上游拉取”。自行维护包括自建内容及明确接管的本地改编，不代表认定全部内容由用户原创；来源未核实的资源保留说明。已存在的 Claude/Cursor 文件及原生 Hook 运行依赖按其实际路径登记，不新增这些客户端的运行时适配器。

已有文件必须匹配经过 MR 审核的接管指纹，才能记录所有权。内容不匹配继续报冲突，不覆盖本地改动。已确认的上游内容在网络暂时不可用时可以先接管既有指纹，刷新失败仍单独报告。普通未纳管文件保护没有放宽。

启动先完成本地接管、自维护内容应用和采集索引，再刷新上游；尚未刷新的内容标记为同步中。无关的旧投放在完整计划就绪后才清理。MCP 按原生配置文件与作用域独立登记，缺少一个本机凭据不会阻塞无关规则。

ECC 从上游正式发布的 npm 包获取，通过原生 Skill 安装器生成选定内容；命令模板与 Agent 定义由 Rust 转换为原生格式。已确认来源的其他项目 Skill 也交给原生安装器。上游内容没有复制进 SM，也不参与本地优化。ECC 已移除的 motion-ui 保留现有内容并转为自维护，来源说明随资源保留；其他来源未确认的本地改编也明确标注，等待进一步核实。

Codex/Kimi 插件使用各自原生生命周期更新，不复制插件缓存。插件声明与启停意图由 SM 管理；页面的“申请启用/禁用”创建 MR，经审核合并、下一次同步后生效。运行时凭据、原生信任状态和会话数据不进入资源仓库；需要本机值的配置可使用同位置 `${SM_LOCAL}` 绑定。插件失败保留错误状态和经过重新核验的既有安装记录。

旧仓库迁移遗留的三个失效 Claude Skill 链接按清单精确清理：只删除仍指向声明旧位置的悬空链接。用户改过的链接、普通文件或已恢复有效的链接都保留并报冲突。项目 Skill 不通过用户级别名重新扩大作用域。

检查范围是当前用户及清单约定的项目目录；系统级资源、客户端自身的内置资源和认证/历史数据继续由原生平台维护。原生插件/文件已登记与 Agent 实际加载成功分别展示；新插件通常需重新加载或开启新会话。
