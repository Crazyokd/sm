## 接管规则

- 自建内容包含脚本、附件和执行位；easygo-deploy-dev-hot-update、easygo-package-tag-mr 及五项 SROS 仿真 Skill 采用本机较新的项目内容，其余采用旧仓库当前工作树。forge-current-session 的脚本入口改为通用 .agents 路径。
- remote-build、sim-deploy、sim-stability、sim-test、sim-tag-deploy 归属 sros-core（最后一项虽然原归档在 easygo-app，脚本实际依赖 SROS simulation）；EasyGo 专用 Skill 归属 easygo，避免投放到用户级。
- vue-best-practices 与 vueuse-functions 已从原聚合仓库移出，改登记维护者的独立上游仓库。
- 上游来源来自原安装锁、Skill 自带来源元信息及第三方登记。使用 Skills CLI 仅在临时项目恢复所选 Skill，SM 再投放到声明的 .agents/skills。生成器中的 --agent codex 只决定上游工具的暂存输出，不产生 Skill 的客户端维度。
- 上游内容跟随当前默认分支或官方站点，不进入自建优化。skills@1.7.2 固定恢复工具的依赖；资源本身没有多版本选择。
- 本机旧安装在接管前保留私有备份；SM 不自动覆盖无主文件。重复的 Codex 安装副本在确认通用目录可用后移出，避免独立副本遮挡更新。
- 原归档 Git 历史、未提交差异和工作树完整备份后才能删除旧目录。项目中既有的跟踪文件可能随 SM 同步产生差异；后续资源维护以 SM MR 为准。

| OpenSpec | npm @fission-ai/openspec，原登记 1.2.0；openspec init --tools codex --force <临时项目> | 项目生成器，当前未登记具体生成 Skill |
