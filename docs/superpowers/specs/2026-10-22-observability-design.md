# SM 运行记录与诊断

用户已要求全部实施前次评估的五项改进：运行可追踪、页面健康状态、优化证据、留存边界、脱敏诊断导出，并精简普通文件所有权状态。继续使用 Rust 1.88、严格 TypeScript、SQLite、本地 JSONL 与 journald；自建修改仍经 MR，禁止调用导入的业务脚本或自动合并优化提案。

## 运行记录

每个同步、夜间任务与初始化有任务 ID、触发来源、开始/结束时间、状态、耗时、阶段、当前资源、完成/总数及失败摘要。只记录阶段、资源结果与总体结果，不逐文件输出。当前运行快照存在 SQLite `active_run`；最终记录复用现有 `runs`，在 result.run 保存强类型元数据，保留原业务结果结构与最近 100 次记录。journald 输出脱敏 JSON 生命周期事件。异常退出后，下次取得作业锁将遗留运行标记中断；读取健康状态须识别已失去作业锁的遗留快照。

子进程超时保留有长度上限的脱敏 stderr 尾部、超时阈值、程序和退出状态；不记录完整环境或成功输出。启动同步的错误应在任务结束时立即报告，不等 Web 关闭。

## 采集与证据

Hook 继续只写本地，不连接数据库、网络或模型。每个客户端的私有健康文件记录最后收到时间、事件计数、失败计数、缺口/截断数量和有限错误摘要；并发更新不能丢计数。内部运行不计入。

记录明确信号与未知：文件读取、客户端明确报告启用、工具执行；能从原生 payload 得到的成功/失败、退出码、耗时与有界结果摘要保留，缺失不推断。完整输出仍只存摘要哈希。会话、事件 ID、资源内容哈希用于证据关联；路径匹配不称作完整 Skill 执行。

## 留存与体积

初始默认：原始/已处理详细记录保留 14 天，原始文件目标上限 50 MiB。只删除已完整消化的关闭文件；部分尾行、尚未处理的记录和 MR/提案/发现引用的数据库证据受保护。保护数据导致超限时明确显示超限与原因，不能静默丢弃。保留长期每资源的事件总数和最近时间，避免清理后统计归零；不得把事件数称作使用次数。自动清理在夜间任务内、作业锁下进行，记录清理前后大小和保护计数。

普通文件所有权只保存 SHA-256 与执行位；JSON/TOML/Markdown 共享内容保留必要合并片段。现有文件正文记录在事务内一次转换，不清空状态，不修改投放文件；转完压缩 SQLite 空闲页。不保留旧仓库备份，也不新增平行版本或兼容运行路径。

## 健康与导出

运行页展示当前任务/阶段/进度、最近成功与失败、客户端最后事件、待消化与待分析数量、解析/采集错误、磁盘占用和留存状态。页面打开不触发同步/分析，健康查询不修改任务状态。

CLI `sm diagnose --output <文件>` 与运行页下载按钮生成同一份脱敏 JSON：程序与客户端版本、仓库已批准 revision、服务状态、当前/近期任务、资源结果、采集/积压/留存统计和有限错误。不主动收集完整资源正文、工具输入输出、配置或环境变量；有限错误上下文使用模式脱敏，不能证明任意业务文字均不敏感。输出文件 0600，HTTP 下载私有且禁止缓存，保留现有 Host/Origin 约束。导出总量限制 256 KiB，超限省略旧明细并计数，保留完整状态总数，不修改原始历史。

## 验收边界

测试使用隔离临时目录与可控子进程，覆盖并发采集、失败/超时/中断、隐私、保留引用与部分记录、重复消化不重复统计、所有权迁移后本地修改/权限/共享配置保护、CLI 和页面诊断一致性。浏览器检查真实页面及窄屏。通过 MR/主分支 CI 后更新本机二进制；实际夜间模型优化质量与第二台机器继续单独标记未验收。
