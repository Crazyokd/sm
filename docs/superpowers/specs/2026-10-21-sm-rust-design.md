# SM 强类型实现迁移

本次依据用户“下一版使用成熟的强类型语言，按要求修改”的明确指令执行。产品行为沿用已确认的第一阶段需求，不新增资源版本、分支选择或双实现运行模式。

## 目标和技术选择

核心由 Python 全部迁移为 Rust；浏览器逻辑由 JavaScript 源码迁移为严格模式 TypeScript。Rust 是实现者选择：编译期类型检查、枚举约束非法状态、明确的错误传播，以及可独立运行的本地可执行文件。Axum 处理本地 HTTP，MiniJinja 复用现有页面，rusqlite 保持本地数据库格式，toml_edit 保留无关原生配置。

CLI 子命令保持 init、serve、sync、cycle、record、status、propose。初始化仍是 clone 后执行 ./sm init；构建需要 Rust 工具链，运行不需要 Python 或 Node。前端编译产物随源码提交，TypeScript 的严格检查和产物一致性纳入验证。

## 保留契约

- catalog.json 的五类资源、来源和作用域格式保持兼容。Skill 单一 payload，不按客户端分类，只投放一份共享内容。
- 原 SQLite kv／ownership／observations 表、所有权编码、JSONL、记录偏移、内容哈希和待审提案仍可读取，不清空、不重置、不要求重新收集记录。
- 明确类型表示资源、客户端原生格式、来源、作用域、写入模式、应用状态、候选操作和验证报告。任意 JSON 只用于原生配置或 Hook 事件等真实开放边界。
- 自建内容只来自远端已合并 main；上游直接同步、不分析；用户／AI 修改均经 MR 后再同步。
- 保留原有配置、凭据、受管文件修改冲突、共享目标冲突传播、旧位置清理和附件执行位。
- 保留记录脱敏、去重、缺口与事实／推断区别、禁止分析器执行业务工具、原始评估约束、部分验证和 Draft MR。
- 保留四个前端视角、阅读和筛选、创建／编辑／改名／归属／移除提案、CSRF、Host／Origin 与输出转义边界。
- 初始化重建当前用户的同名 systemd 单元和采集命令，使其指向 Rust 程序；项目开发不直接初始化真实用户账户。

## 迁移与回退

在隔离分支完成全量替换，验收后移除 Python 包、Python 启动入口和测试依赖，不留下运行时转发 Python 的包装层。Git 保留上一版实现供回退；数据库布局和事件格式不做破坏性修改，因此回退不会丢失本地状态。用户若已经初始化旧版，更新后重新执行 ./sm init 切换服务程序；旧采集入口的在途事件继续可消化。

## 验收

1. Rust 编译、格式、Clippy、行为回归通过；TypeScript strict 检查和编译产物一致。
2. 用上一版实际生成的状态／事件夹具证明新程序读取已有所有权、提案、偏移和记录，不产生重复配置。
3. 用临时 Git 远端和两个用户目录证明审核后生效、作用域、上游、不覆盖本地内容及组织变化的行为。
4. 用真实可执行程序和 HTTP 检查七个 CLI 子命令与 Web 请求；模型、systemd、GitLab 的副作用只在隔离替身中执行。
5. 原五类资源读取、前端创建与重命名、MR 关联和移动端布局使用 browser-harness 实测。
6. Python 资源的语法检查由原生解析器完成，不为被管理资源检查而重新引入 Python 运行时。

已知边界继续沿用第一阶段：静态／文本检查不证明业务优化收益；原生 Hook 全覆盖、真实账户服务和生产任务另行验收。本次不执行生产 MCP、机器人任务或真实用户初始化。
