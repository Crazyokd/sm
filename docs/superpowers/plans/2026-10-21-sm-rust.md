# SM Rust Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 将已确认的 SM 功能完整迁移到 Rust 和严格 TypeScript，保持数据和行为兼容，移除 Python 运行依赖。

**Architecture:** 一个 Rust 可执行程序包含 CLI、本地 HTTP、同步应用、记录分析和 MR 流程。Serde 枚举／结构体定义领域契约，SQLite 与 JSONL 沿用旧格式，模板与静态资源嵌入二进制，前端保留现有布局。

**Tech Stack:** Rust 1.88+；Axum／Tokio、Serde、rusqlite、toml_edit、MiniJinja、pulldown-cmark、Clap；TypeScript strict；Git、glab、systemd。

**Spec:** ../specs/2026-10-21-sm-rust-design.md；产品依据 ../specs/2026-10-21-sm-design.md。

## Global Constraints

- CLI、catalog.json、SQLite／JSONL、资源目录约定与第一阶段兼容。
- Skill 本体与客户端无关，内容和共享生效目录各一份。
- 自建内容仅远端 main 生效，任何修改都先 MR；上游直接跟随且不分析。
- 不丢失既有状态和记录，不覆盖无关原生配置或凭据，不自动初始化真实用户。
- 核心使用明确结构体和枚举，动态 JSON 限于原生配置／事件等开放边界；无 Python 运行时转发。
- 维持当前单份资源内容；不增加产品层多版本／通道。

## Review Focus

1. 旧版 SQLite／事件／提案读取失败、内容哈希变化或所有权重复，不能通过清空状态掩盖；Task 1、3、6。
2. 迁移配置合并时丢失注释／本地值、移动失败删除旧位置、执行位遗漏或路径逃逸；Task 1、2。
3. MR 续写在 main 前进后仍可推送，项目映射必须约束全部受影响资源，证据和 Draft 状态须刷新；Task 2。
4. 模型输出、损坏事件和非法 HTTP 输入应返回可见错误，不能 panic、越界或在异步线程阻塞；Task 3、5。
5. 编译产物与 TypeScript 漂移、嵌入页面遗漏、原生服务／采集仍指向旧 Python；Task 4、5、6。
