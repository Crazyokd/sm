# Terminal Image Pane

沿用用户现有的 Alacritty + tmux，在当前对话所在窗口分出专用图片窗格，默认放在右侧。用户指定下方时使用下方。让聊天、输入和图片同时可见；应用本身无需实现图片协议。

## 展示流程

1. 确认图片存在并检查内容。图片生成仍由对应的画图或截图工具负责。
2. 确认用户的对话窗格和真实桌面环境。工具进程的 `TMUX_PANE`、父进程和“当前活动窗格”可能属于另一段会话，不能直接作为依据。通过窗格标题、目录以及近期用户消息交叉定位；只读取定位所需的少量内容，不输出其他会话全文。
3. 优先复用 `~/.local/bin/term-image`，用 `--help` 确认支持 `--right` / `--below`。不存在或缺少分栏功能时，直接使用包内的 [scripts/term-image.py](scripts/term-image.py)，不要覆盖已安装版本。
4. 用 `--right` 或 `--below` 创建图片窗格。保留 `-d` 的行为，聊天输入焦点留在原处。已有右侧图片区时，将后续图片放到图片区下方，避免不断压缩聊天宽度。记录本次创建的 pane ID。
5. 核对实际终端画面：目标会话正确、图片未遮住聊天、内容可辨认，多张图片同时存在。后台进程、X11 窗口或工具 PTY 的存在都不能独立证明用户看到了图片。

在用户自己运行命令的正确 tmux 窗格中：

```bash
term-image --right "$image_path"
term-image --below "$image_path"
```

代理代用户打开图片时，先读 [references/agent-display.md](references/agent-display.md)，按已核实的目标 pane 显式传入环境。不要把命令文本打入正在运行的聊天应用。

## 多图与退出

- 每张图占一个独立窗格；可以关闭其中一张而保留其他图。聚焦图片区后按 Enter 或 Ctrl+C 退出，辅助程序创建的窗格会随之关闭。
- 保留用户已有窗格和布局；只清理本次创建且明确归属本次展示的进程、窗格与 hook。
- 需要更大画面时只调整相关窗格，或重新生成适合窄栏的图片。不要为了看图新开终端、切换终端软件或改全局配置，除非用户要求。
- 不在聊天窗格直接运行不带分栏参数的预览，也不在聊天区域叠加浮层；那会占用或遮挡输入。

## 依赖与证据边界

这条路径依赖 tmux、Python 3 和已配置的 `~/.local/bin/ueberzugpp`，使用本地 X11 的 `DISPLAY`。它不要求 Alacritty 原生支持 SIXEL 或 Kitty Graphics。在其他桌面环境中先验证现有渲染器，不把 X11 的成功推广为 Wayland 原生支持。

包内辅助程序保留已验证的多图 hook 隔离：只为 ueberzug++ 子进程提供私有 tmux shim，按进程使用独立的全局 hook 数组槽，退出时只移除自己的槽。该适配针对 ueberzug++ 2.9.10；升级后按参考文件复核，不能恢复为会覆盖其他预览的无索引 hook。

无法定位真实终端或缺少显示依赖时，交付可点击的图片路径和准确命令，并明确终端显示未验证。有多个无法区分的候选窗格时才询问目标。保留“图片已生成”“已检查图片内容”“已核对终端显示”三个证据层次。

这提供同一终端中的图片分栏，图片不会随聊天消息滚动。
