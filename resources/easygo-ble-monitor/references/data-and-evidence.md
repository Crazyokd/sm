# 数据与证据边界

## 会话与文件

`prepare.py` 把运行程序复制到独立工作目录；安装树保持只读。`targets.json` 只在本地填写，`active.json` 指向当前会话。开始时冻结固定地址、SSH 通道、robot_id 和蓝牙 MAC，不能每轮重新解析可变化的别名。

每次会话使用新的 UTC 时间与随机后缀目录。会话内的 `session.json` 保存固定身份、包版本、bridge 启动时传输选择、记录器进程与位置；不保存完整环境或凭据。

| 文件 | 用途 |
| --- | --- |
| `wx1-facts.jsonl` / `wx2-facts.jsonl` | 车端实际收到的 ROS 事实和 API 状态的本地增量镜像 |
| `feedback.jsonl` | 每 5 秒的配对快照，含查询时间、定位和计数 |
| `latest.json` | 侧栏当前快照；不是原始数据替代品 |
| `wx1-source.tar.gz` 等 | 结束后完整的 ROS/API 原始记录、状态、启动元数据和错误 |
| `wx1-radio.tar.gz` 等 | HCI btsnoop、无线状态、资源记录及错误 |
| `archives.json` | 已取回归档的大小与 SHA256；未启动组件明确注明 |

原始消息按收到的内容保留。归档计数与末尾结束证据用来核对保存完整性，不代表源发布端每条消息都被探针观察到。原始文件保留在车端直至取回；网络断开或取回失败时明确标记待恢复。

分析中 `capture_complete` 表示已捕获事件流的完整性，`data_quality` 另列无效帧和 API 采样错误；完整保存错误记录不等于测量没有质量缺口。HCI 只检查文件头和基本尺寸，未逐包验证。

## ROS 事实的真实结构

记录行共用 `kind`、`own_id`、`epoch_ns`（接收端墙钟）和 `mono_ns`（接收端单调时钟）。

self.data 是平铺的 LocalGeometry，**没有 robot_id 或 geometry 包裹**：

```json
{"map_id":"map-a","sampled_at_ns":1000000000,"pose":[1.0,2.0,0.0],"velocity":[0.0,0.0,0.0],"footprint":[[-0.4,-0.2],[0.4,-0.2],[0.4,0.2],[-0.4,0.2]]}
```

peer.data 包含 `robot_id`、16 字节 `instance_id` 和 `geometry`，其中 geometry 就是上述结构。peer 记录行还保留该帧的 `robot_id`。其他邻车也记录，只有选定 peer_id 用于所选双车方向统计。

self 的来源通过实际机器、API MAC、唯一 bridge 进程及其 ROS 环境绑定；不要校验一个契约中不存在的 self.robot_id。ROS 话题里的 peer 身份是应用声明的身份；需要物理发射端关联时，应再对照广播标识、MAC 和 HCI 证据。

ROS 几何的 x/y 为米、yaw 为弧度；API 位姿 x/y 为毫米、theta 为毫弧度。位置和轮廓引用同一车体原点。地图名称相同并不自行证明坐标基准相同，现场对比需核对实际地图资源。

## 时间、计数和距离

- `raw_source_age_ms = (receiver.epoch_ns - geometry.sampled_at_ns) / 1e6`，保留负值。这包含时钟偏移、发布、传输和采集，不是纯链路时延。
- 用原始 sampled_at_ns 对应发送端 self 与接收端 peer；没有匹配证据的帧另计，不补造源样本。
- 接收间隔与断流使用同一接收端的 mono_ns。包含录制窗口内首帧前、末帧后的静默；没有观察到的时间段保持未知。
- 本分析器不应用时钟校正，`corrected_one_way_latency_ms` 保持未知。若另做校时分析，需要覆盖相关时间段的校时记录及误差边界；不能拿旧时钟快照套用整个长记录。
- self 是探针收到的源消息计数，不是确认的无线发送次数。发送节流、快照合并和重复样本存在时，不用 self-peer 数量差推导丢包率。
- API 与 self 的原值都保留。未知置信度、未知 CPU、未知 RSSI 不改成零；有效零帧或零 CPU 与未知分开表达。
- 配对距离从同一 feedback 快照内的有效同图位姿重新计算，检查采样与查询新鲜度；轮询并非严格同步测量。低或未知置信度标为估计。
- 距离时间线保留累计接收、相对前一有效计数的变化和观察到的断流间隔。首个计数、缺失或重置后的增量保持未知。
- 一米距离分桶归属快照时刻。带新帧/无新帧的统计是该快照前轮询窗口的观测，不是精确无线覆盖概率或可靠最大范围。

## 无线和资源

`radio.jsonl` 中 Connected、ServicesResolved 和缓存 RSSI 是辅助观察，不替代完整 peer 帧。RSSI 属性可能来自较早广播；已连接时可能没有该字段。btsnoop 记录控制器/HCI 边界，不能把其字节数当作完整空口开销。

记录器结束与采集覆盖分开判断。HCI/资源子进程退出、无线属性读取错误、记录缺失或部分镜像均在报告中注明；保留已获得的有效测量，不伪造缺失区段。

资源 CPU 按单核百分比，可超过 100%；RSS 以 MiB（1024² 字节）报告。按进程名汇总或所跟踪进程合计不等于整机使用率；Nav2 容器总消耗也不是邻车层的增量消耗。

## 结论边界

传输、Nav2 消费与行为效果分别取证。ROS peer 帧到达只证明事实桥交付；消费者还会检查身份、地图、新鲜度和实例。证明避障提升需要相同场景的可比较行为证据，例如提前停车、最小轮廓间隙、完成情况与耗时。

先准备不读车、操作者自行挪车等角色分工必须保持。记录过程中零收包或断流不授权自动重启、改参数、清缓存、部署、定位或发任务；需要这些动作时沿用明确的本次授权并另记事件。
