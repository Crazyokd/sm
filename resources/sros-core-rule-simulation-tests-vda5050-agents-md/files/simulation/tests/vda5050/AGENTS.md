# Agent 开发规则

## Git 开发流程

每次开始开发前必须执行以下流程：

1. 检查工作区状态，保留并识别用户已有改动，不得擅自覆盖或删除。
2. 获取远端最新代码，将本地主分支以 fast-forward 方式更新到 `origin/master`。
3. 从最新主分支创建新的开发分支，禁止直接在主分支上开发。

参考命令：

```bash
git status --short --branch
git fetch origin --prune
git switch master
git pull --ff-only origin master
git switch -c <开发分支>
```

开发完成后必须：

1. 执行与改动范围匹配的验证，并记录验证结果。
2. 只暂存本次改动，不得提交无关文件、凭证、运行产物或 IDE 配置。
3. 提交代码并推送开发分支到远端。
4. 创建目标分支为 `master` 的 Merge Request。

## MR 标题

MR 标题必须使用中文，并使用以下格式之一：

```text
fix: 修复内容
feat: 功能内容
```

- 修复缺陷使用 `fix:`。
- 新增功能、测试能力或自动化覆盖使用 `feat:`。
- 冒号后保留一个空格，标题正文使用中文。

## MR 描述

MR 描述必须使用中文 Markdown，并至少包含以下内容：

```markdown
## 改动范围

- 说明修改的模块、文件或功能。

## 改动原因

- 说明问题背景和修改目的。

## 影响范围

- 说明对现有功能、兼容性、运行环境或测试资源的影响。

## 验证结果

- 列出实际执行的验证命令及结果。
- 未执行的硬件、集成或破坏性验证必须明确说明原因。
```

MR 描述不得只写“已修改”或“测试通过”，必须提供可复核的改动和验证信息。
