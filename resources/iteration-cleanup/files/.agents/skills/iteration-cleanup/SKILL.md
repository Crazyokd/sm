# simenv 迭代产物清理

仅用于 simenv 项目的构建、仿真与测试迭代。让迭代占用有上限，同时保留可复现的源码和验收证据。每轮开始大构建/录制前，以及归档完成和结束本轮时，都执行一次；不要等磁盘写满。

## 执行

1. 对实际工作目录、数据目录和临时目录所在文件系统检查 `df -h`；用 `du -sh` 定向测量本任务的构建上下文、运行目录和归档。估计下一轮构建、日志、归档及临时副本的峰值，先留够空间再启动。复用已有 run metadata、source manifest 和进度记录，不扫描整个主目录，也不另造重复总账。
2. 以创建记录、完整路径、精确容器/镜像 ID、挂载和当前进程状态确认归属及生命周期。只有旧文件名、目录前缀或 mtime 不足以证明可删。活构建、运行、观察器仍依赖的文件继续保留；观察超时不代表进程停止。
3. 先处理本任务可重建的构建上下文 `rootfs`、已被替代的中间副本和未被引用的临时目录。删除旧 `rootfs` 前核对源码归档 SHA-256、manifest 和构建配方，并确认镜像仍存在且 ID 匹配；也可先无损压缩该目录，逐文件校验归档内容、权限和链接后再删原目录。当前仍需直接使用的上下文保留。只删除明确列出的生成目录。
4. 对旧镜像，保留当前被测/即将复测版本、必要构建基线和明确的回归对照。其他本任务镜像须先保存精确源码、构建配方和验证记录，确认无容器、共享标签或后续步骤引用，再按精确 ID/标签释放。容器通过原编排器按本次归属停止并复查。禁止全局 `docker system prune`、`image prune -a` 或批量清共享卷。
5. 原任务 UUID、源版本、manifest、失败原因、物理真值/contact、MCAP、验证日志及报告引用的证据保留。需要去重或无损压缩时，先核验等价归档并更新引用。不得按年龄删除失败证据、用户数据、源码、工作树或仍需使用的构建前缀。
6. 新归档先写 `.partial`，关闭并校验成功后再改正式文件名。失败保留原始错误和未完成标记；空间不足时先清理本任务可重建产物，再重试同一归档，不能把半成品当作完成。
7. 清理后复查 `df`、保留物和无关容器；把删除清单、核验依据、保留项及前后空间写入本任务记录。并发任务导致的空间变化不归因于本轮。下一轮复用这份记录，避免重新堆出相同副本。

已获授权的本任务可重建产物自主清理。未知归属、仍在用或缺少恢复依据的项目保留并说明；不为腾空间扩大删除范围。磁盘紧张时先暂停新增大产物，清理后继续原任务，不缩减验收或丢弃反例。
